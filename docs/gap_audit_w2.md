## Top findings

1. **M8 scoring is 🔄 by design and correct**: real BMSD 2026 (chicken=10 + 1/finish) replaces the PRD's generic table, AND it is fully configurable per tournament (`points_calculator.py` + `tournaments.placement_points` JSONB + `points_per_kill`), so the PRD table remains enterable as config.
2. **Damage is the sharpest M7 split (High)**: honestly computed from HP drops in `team_tracker.py`/`fight_detector.py`, but the HTTP analytics summary estimates it as `kills×120` (`main.py`) — contained only by the DEMO_MODE gate.
3. **Two standings sources of truth**: tournament-configured `PointsCalculator` vs the Redis-hash `PointsEngine` (finishes-only, no placement points, no Redis pub/sub channel).
4. **Healing and grenades are recorded but never published**: agent-level counters exist; `MatchPlayerStats` has no fields for them, so they die in memory.
5. **Zone efficiency is the only outright ❌** in M5–M8; aggression exists as two disconnected implementations (live 1–10 heuristic vs stored 0–1 DB score nobody writes).
6. **Director (M6) is the strongest module**: 10s min-scene, clutch override and 3 modes are exact or better; gaps are the missing 3s cooldown constant, priority-without-hard-lock in the final zone, and `should_switch()` existing as a pipeline (+ `IntensityScorer.compare_fights`) rather than a named function.
7. **M5's "16 FastAPI microservices" is really 16×4 in-process agents** in one FastAPI app — functionally complete, architecturally different from PRD wording.
