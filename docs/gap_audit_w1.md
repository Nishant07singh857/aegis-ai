# Gap Audit W1 — PRD v2.0 Modules M1–M4 vs Actual Codebase

**Scope:** `backend/app/vision/**`, `backend/app/agents/fight_agents/**`, `backend/app/db/models/observer_slot.py`, `backend/app/db/models/fight_event.py`, `backend/app/api/v1/observers/**`. Every file below was read as real code (line counts 211–1,198 lines per file — none of the audited vision/fight files are one-line placeholders).

**Method note — two generations of code exist:**
- **Gen-1 (agent-era library):** `vision/capture/device_manager.py`, `vision/capture/feed_health_monitor.py`, `vision/models/*_service.py`, most of `vision/detectors/*.py`. Real, substantive implementations, but several are **not wired into the live pipeline**.
- **Gen-2 (Phase 14/17 production path):** `vision/capture/frame_grabber.py`, `vision/capture/multi_device.py`, `vision/detectors/killfeed.py`, `vision/detectors/hud.py`, `vision/runtime.py`. `runtime.py` registers **only 4 detectors**: `KillFeedDetector`, `AliveCountReader`, `ZoneTimerReader`, `TeamStatusReader`. Most 🟡 PARTIAL verdicts below mean "real code exists in Gen-1, never carried into the Gen-2 runtime."

## Key questions answered

- **16 vs 40 devices:** The manager covers exactly the **16 Team Observer slots** (1 per team — the project's deliberate 16-team BGMI format). The other 24 PRD devices (Map ×4, Final Zone ×2, Hotspot ×10, Backup ×8) have **no device, slot, or role representation anywhere**. `MAP_OVERVIEW` / `FINAL_ZONE` exist only as logical feed-type labels in `agents/observer_agents/pov_selector.py`, not as physical devices.
- **Which OCR?** **Tesseract is the production OCR** (`detectors/killfeed.py` documents the choice explicitly; `detectors/hud.py` `TesseractEngine` + OpenCV `TemplateDigitEngine` fallback). `PaddleOCRService` is a complete wrapper but is **not in the production pipeline**; `paddleocr` is only an optional `ml` extra in `backend/pyproject.toml`, lazily imported by a few non-wired Gen-1 detectors.
- **Which detectors actually exist?** All PRD detectors exist as real code (HSV/YOLO logic, several with unit tests). The catch is wiring: only kill feed, alive count, zone **timer**, and team-card status run live. HP bars exist and are tested but are not registered in `runtime.py`. ByteTrack exists as a service but nothing in the live path calls it (`PlayerTracker` does its own distance matching). Smoke / vehicle / weapon detectors exist but are not wired. **Parachute phase does not exist at all** (zero matches for "parachute" in `backend/app`). Helmets/vests have no dedicated detector.
- **Fight detection — which of the 8 signals are real?** Fully real producers exist for only **3**: kill feed, HP drop, proximity (but at **150 m**, not the PRD's <50 m). Grenade + smoke exist only as a combined `process_utility()` API with **no automatic producer**. Down count exists only as the `is_knock` flag inside the kill-feed signal. **Audio gunshots and squad-size delta do not exist.**

## Top findings

1. **The 40-device PRD fleet is really a 16-device system.** All 16 slots are Team Observers; Map/Final-Zone/Hotspot/Backup device classes (24 devices) don't exist in any form. This matches the project's deliberate 16-team BGMI scope, but against PRD v2.0 as written it is the single largest gap.
2. **Latency/timestamp sync (±500 ms) is completely unimplemented** — the only wholly absent *quantitative* spec in M1/M2. Frames carry server grab-time stamps; there is no mechanism that could even measure cross-feed drift, let alone correct it.
3. **The CV engine is wide but shallow in production.** 12+ detectors exist as real code, yet `vision/runtime.py` runs only 4 (kill feed, alive count, zone timer, team status). HP bars, minimap, zone circle, smoke, grenade, vehicle, and weapon detectors are all built-but-unwired Gen-1 code.
4. **Production OCR is Tesseract, not PaddleOCR** (🔄, deliberate and documented in `killfeed.py`, zero-cost/local). PaddleOCR, YOLOv8, and ByteTrack all exist as genuine service wrappers (`vision/models/`) that the live pipeline never calls; the only trained-model path actually wired is the kill-feed ONNX hybrid (`ml/vision_wiring.py`).
5. **Fight detection runs on ~3 of 8 PRD signals.** Kill feed (fully chained from CV), HP drop (threshold only — no velocity math, and no live HP producer), and proximity (150 m instead of 50 m, no live position producer). Grenade/smoke are an uncalled API; down count is a kill-feed side-effect; **audio gunshots and squad-size delta are absent**.
6. **Two "built but orphaned" integrations recur:** `FeedHealthMonitor`'s record methods and `DeviceManager`'s health model have no callers in the live path, and manual observer reassignment exists (`PUT /observers/{slot}/assign`) with no automatic trigger on failure or elimination.
7. **Ingest protocol coverage is ADB-first by design:** ADB/scrcpy ✅ and RTMP ✅ are real; OBS is output-side + virtual-cam workaround (🔄); WebRTC ❌ and NDI ❌ (NDI stubbed honestly — it reports no-feed rather than faking frames).
