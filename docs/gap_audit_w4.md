## B) Agent Architecture

**Headline finding: the "~40 agents" count is real, the "separate FastAPI microservices" claim is false.** There are **41 `BaseAgent` subclasses** (42 class definitions including `BaseAgent` itself) totalling **~27,600 lines** in `backend/app/agents/` — every file is a substantive implementation (235–1,036 lines; no one-line placeholders in this tree). They run as an **in-process library inside the single monolithic FastAPI app** (A1): one `AgentOrchestrator` (`backend/app/agents/orchestrator.py`, 870 lines) + one `AgentRegistry` (`agent_registry.py`, in-process dict) + one shared `EventBus`. There is exactly **one backend Dockerfile**; no per-agent service, port, or deployment unit exists.

> **CORRECTION (2026-10-24, Integrity Fix Pack — inspection H5/H32):** "They run as an in-process library" needs its dormant half stated plainly: **the agent system does not run in production at all.** `AgentOrchestrator` is never imported or started by `app/main.py` (its only callers are a smoke script and e2e tests). Production directly instantiates only **6 agent classes** — FightDetector, TeamTracker, UtilityTracker, StorytellerAgent, VoiceSynthesizer, LanguageManager — plus **3 function-modules** (MVP `compute_mvp_score`, win-probability, day-reel); the other 34–35 classes never execute. The orchestrator also no longer constructs the deprecated second director stack (ObserverDirector / POVSelector / SafetyController / PlaybookManager — superseded by `services/live_director`).
