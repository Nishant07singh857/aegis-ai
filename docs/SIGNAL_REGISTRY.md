# SIGNAL REGISTRY — Every Spectator Signal & Derivation in AEGIS

**Phase 24 · W4 — Future-proofing**
**Date:** 2026-10-20 · **Companion docs:** `docs/SPECTATOR_COVERAGE.md`
(§1 coverage matrix — the audited source for every Layer 1 row below;
§3 Limitations Register — the fundamental limits this registry points
to, never duplicates) · `docs/PROJECT_INVENTORY.md` (counts, honest
verdicts) · `docs/BGMI_TERMS_AZ.md` (broadcast vocabulary).

**Purpose.** One declared home for every signal AEGIS captures,
derives, or plans to derive from spectator mode. A future feature
plugs in by adding a row here and following the pipeline below — it
never rewires producers or consumers ad hoc. If a signal is not in
this registry, it does not exist for AEGIS.

**Worldview (standing directive).** Spectator/observer mode ONLY.
There is no game API, no telemetry, no server feed. Anything not
visible on an observer phone screen (or tappable by a human spotter
watching one) does not exist for AEGIS.

---

## How to add a new signal (read this first)

1. **Declare it here first.** Add a row to the correct layer table
   below *before* writing code: name, spectator source, intended
   producer, transport & storage, consumers, and the honesty rule
   for missing input. A row with no honesty rule is not accepted.
2. **Producer.** One module owns capture/derivation. Vision
   producers live in `backend/app/vision/detectors/` and are wired
   in `backend/app/vision/runtime.py`; derivations live in
   `backend/app/agents/` or `backend/app/services/`. A detector that
   exists on disk but is not wired in `runtime.py` is **not** a
   producer — the registry row must say so.
3. **Transport.** Publish on the event bus
   (`backend/app/core/event_bus.py`) with a stable snake_case event
   type (`hp_update`, `zone_event`, `loot_event`, …). Bus events
   persist generically to the `event_store` table via
   `event_bus._persist_event`; add a dedicated table (new Alembic
   migration) only when a live writer actually writes structured
   rows consumers query. Long-lived derivation state may be
   in-memory, and the row must say so (it dies on restart).
4. **Consumer.** Name every consumer in the row. Consumers read the
   bus event / table / service snapshot — never another producer's
   internals. Observer-slot → team attribution follows
   `services/vision_intelligence/attribution.py`: unmapped slots are
   dropped, a team is **never** guessed.
5. **Honesty rule.** State what happens when the input is missing:
   `null` / `"—"` on display, the derivation stays silent, or the
   value is labelled inference with its source in the payload
   (precedent: `phase_source=inferred_from_timer_reset`). Inventing
   a value — an estimated damage number, a guessed team, a fake
   countdown — is a registry violation.
6. **Verify.** Add/extend tests, then update the §1 matrix in
   `docs/SPECTATOR_COVERAGE.md` so the audit and this registry never
   drift apart.

**POI naming.** Any signal that names a place does it through the
POI database (`backend/app/services/poi/poi_database.py`,
`get_poi_database().nearest(map_id, x, y)`) — see Layer 3, row P0.
No module keeps its own place-name list.

## Fundamental limits (pointer — do not duplicate)

Every row below is bounded by the **Limitations Register in
`docs/SPECTATOR_COVERAGE.md` §3 (L1–L12)** — properties of watching
a rendered client that no detector, model, or future phase changes.
Read that register before designing a signal; this registry does not
repeat its content.

Three limits the W1 audit found only **partially** stated in AEGIS
docs/UI today — flag them in any row that touches them:

* **L2 — enemy inventory / loot-in-hand** (see §3): never claimable
  from a spectator feed; crate *presence* is all a loot signal has.
* **L9 — blind spots: events outside every observer's view**
  (see §3): 16 slots still render only 16 chosen POVs; absence of a
  signal is never proof an event did not happen.
* **L11 — spectator delay (~30 s–1 min)** (see §3): every "live"
  signal describes the delayed world, not the game world.
